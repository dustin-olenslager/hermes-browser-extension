Annotations — the parts a wireframe must state

  • Purpose: settle the pairing screen — what the operator types, what he must be able to see, and what must be impossible to do by accident.
  • Screen: the extension popup, 340px wide. One screen, no navigation, no second page.
  • State shown: the four states are drawn below rather than one, because the state IS the screen — the operator's only question is "is it connected, and if not, why".
  • Deliberately absent: real copy, brand colour, imagery, motion — and, by decision, an options page, a per-site allowlist editor (the list is one text field in this same popup, not a screen), and a log view (see the plan's deletion candidates).
  • Not wired: nothing is clickable. The interactions are listed, not built.
  • Interactions to design against: the reviewer should judge the four states and the refusal text, not the styling.

Connecting to <server>…

Connected — this browser is the agent's controller

Names the session it serves. Disconnect is enabled; Connect is not.

Fatal (bad key / bad session)

Rejected — check the access key

Stops retrying and says so. This is the state that must never look like Connecting: a silent retry loop is indistinguishable from a working socket (US-5).
